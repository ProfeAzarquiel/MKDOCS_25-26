    Configuración, instalación y recuperación del software base

Cada apartado indica el criterio de evaluación (CE) del currículo con el que se relaciona.

    1. Configuración del arranque

    Criterios relacionados: CE 3.3 (secuencias de arranque), CE 1.4 (parámetros de configuración).

    1.1. El proceso de arranque

    El arranque de un equipo avanza en cuatro fases:

    1. POST (Power-On Self-Test): al encender, el firmware comprueba CPU, memoria, tarjeta gráfica, teclado y unidades. Si falla, detiene el arranque e informa mediante pitidos, códigos en pantalla o LED de diagnóstico (cada fabricante publica su tabla: por ejemplo, en Dell 2 pitidos indican RAM no detectada) (Dell: códigos de sonido, HP: indicadores de diagnóstico).
    2. Firmware (BIOS/UEFI): consulta su lista de dispositivos por prioridad (secuencia de arranque) hasta encontrar uno arrancable.
    3. Gestor de arranque: en BIOS lee el primer sector del disco (MBR); en UEFI carga un archivo ejecutable EFI desde la partición de sistema EFI (ESP), según la documentación de Microsoft sobre UEFI y GPT.
    4. Sistema operativo: el gestor (Windows Boot Manager, GRUB) entrega el control al núcleo y se cargan los servicios del sistema.

    1.2. BIOS y UEFI

    El firmware es el primer software que se ejecuta al encender el equipo. La pareja clásica es BIOS+MBR frente a UEFI+GPT (Dell: Boot Mode Considerations, HP: BIOS y UEFI):

    Aspecto BIOS (heredado) UEFI (actual)
    Dónde lee el arranque Primer sector del disco (MBR) Archivo EFI en la partición ESP
    Tabla de particiones MBR GPT
    Interfaz Texto, solo teclado Gráfica, con ratón y red
    Seguridad Contraseñas de Setup Secure Boot: solo cargadores firmados

    Secure Boot es la función de UEFI que verifica la firma digital de cada pieza del software de arranque antes de ejecutarla, impidiendo que rootkits y cargadores no firmados se ejecuten antes que el sistema operativo. Windows 11 lo exige activado (Microsoft: Windows 11 y el arranque seguro). Para arrancar un USB live sin firma (GParted, Clonezilla) puede ser necesario desactivarlo temporalmente.

    1.3. La secuencia de arranque y sus modos

    • Qué es: lista priorizada de dispositivos que el firmware consulta en orden. En UEFI cada entrada apunta a un archivo de arranque concreto, por lo que un mismo disco puede tener varias entradas (Dell).
    • Cómo se cambia: de forma permanente desde el Setup (Supr, F2 o F10 según fabricante), o de forma puntual con el Boot Menu (F8, F11, F12 o Esc) sin modificar la configuración guardada.
    • Modos de arranque configurables:
    • Disco interno: arranque diario del sistema instalado.
    • USB: el firmware carga el cargador del USB como si fuera un disco; instalación de sistemas y medios live.
    • Unidad óptica: arranque desde CD/DVD (norma El Torito); equipos antiguos y discos de rescate.
    • Red (PXE): la tarjeta de red descarga el cargador por DHCP y TFTP; base del despliegue masivo de aulas.
    • Multiarranque: un gestor (GRUB) ofrece un menú con varios sistemas instalados.
    • CSM/Legacy Boot: modo de compatibilidad de las placas UEFI para arrancar medios antiguos estilo BIOS; conviene desactivarlo cuando no se usa.

    2. Instalación del sistema operativo

    Criterios relacionados: CE 3.2 (instalación estándar), CE 3.3 (arranque desde el medio).

    2.1. Requisitos previos

    Antes de instalar un sistema operativo hay que verificar:

    • Compatibilidad de firmware: el equipo debe poder arrancar desde el medio elegido (USB, en la actualidad) y tener el modo adecuado activado (UEFI nativo o CSM según el medio).
    • Requisitos del sistema: espacio en disco, RAM y, en el caso de Windows 11, TPM 2.0 y Secure Boot activado (Microsoft).
    • Licencia y activación: clave de producto o cuenta con licencia digital.
    • Copia de seguridad: si se instala sobre un disco con datos, estos se pierden salvo copia previa.

    2.2. Fases de una instalación estándar

    La instalación asistida desde el medio original avanza por fases:

    1. Arranque desde el medio de instalación (secuencia de arranque configurada a tal efecto).
    2. Configuración inicial: idioma, formato de hora y distribución de teclado.
    3. Elección de destino: selección del disco y de las particiones (el instalador puede crearlas automáticamente o permitir el particionado manual, apartado 4).
    4. Copia de archivos y configuración: el instalador descomprime la imagen del sistema sobre el disco destino y detecta el hardware.
    5. Primera configuración: creación de usuario, región, red, privacidad y actualizaciones.
    6. Postinstalación: controladores que el instalador no incluyó, actualizaciones del sistema y aplicaciones.

    2.3. Variantes de instalación

    • Instalación estándar asistida: la descrita arriba, paso a paso.
    • Instalación desatendida: instala lo mismo pero automatizada con un archivo de respuestas que responde a todos los diálogos (punto intermedio entre la instalación manual y la imagen).
    • Instalación por imagen: se vuelca una imagen de un sistema ya configurado (se desarrolla en los apartados 5 y 8).

    3. Creación de medios de instalación

    Criterios relacionados: CE 3.3 (arranque desde USB), CE 3.5 (utilidades y soportes).

    3.1. Del ISO al USB arrancable

    Un medio de instalación se prepara a partir de la imagen ISO oficial del sistema o de la utilidad (Windows 10/11, GParted Live, Clonezilla Live). El proceso general:

    1. Descargar la ISO desde la fuente oficial y anotar la suma de comprobación publicada (SHA-256).
    2. Verificar la integridad de la descarga comparando sumas (en Windows, certutil -hash archivo.iso SHA256).
    3. Volcar la ISO a un USB con una utilidad de creación de medios.
    4. Probar el medio arrancándolo en un equipo de prácticas con la secuencia de arranque adecuada.

    3.2. Utilidades de creación de medios

    • Rufus: crea USB arrancables desde ISO, con elección de esquema de particiones (GPT/UEFI o MBR/BIOS) y sistema de archivos. Es la opción estándar para un solo medio.
    • Ventoy: permite copiar varias ISO a un mismo USB tal cual y elegir entre ellas desde un menú al arrancar; ideal para un técnico que lleva varias herramientas (GParted, Clonezilla, instaladores).
    • Media Creation Tool de Windows: descarga y prepara el medio oficial de instalación de Windows.

    3.3. Consideraciones prácticas

    • El USB se borra por completo al crear el medio: verificar dos veces el dispositivo seleccionado.
    • El sistema de archivos del USB viene determinado por la utilidad y el esquema elegido; el límite de 4 GiB por archivo de FAT32 condiciona los medios de más de 4 GiB (los instaladores modernos de Windows lo dividen en varias partes por esto).
    • El medio debe ser arrancable en el modo correcto: un USB preparado para UEFI/GPT puede no arrancar en un equipo configurado en modo legacy, y viceversa.

    4. Creación de particiones

    Criterio relacionado: CE 3.4 (herramientas de particionado).

    4.1. Conceptos fundamentales

    • Partición: región del disco delimitada en la tabla de particiones; volumen: espacio de almacenamiento con formato dentro de una partición; letra de unidad / punto de montaje: cómo accede el sistema a cada volumen.
    • Por qué particionar: separar sistema y datos (una reinstalación no toca los datos), convivir varios sistemas (multiarranque) y aislar fallos o llenados entre unidades.
    • Formatear es dar sistema de archivos a una partición: la tabla dice dónde está la partición, el sistema de archivos dice cómo se organizan los archivos dentro.

    4.2. Tablas de particiones: MBR y GPT

    Aspecto MBR (heredado) GPT (actual)
    Particiones primarias 4 (o 3 + una extendida con lógicas) 128
    Tamaño máximo de disco 2 TiB Hasta 18 EiB
    Fiabilidad de la tabla Una sola copia, sin CRC Cabecera y tabla duplicadas con comprobación CRC32
    Firmware de arranque BIOS clásico UEFI nativo (exigido por Windows)

    Fuentes: Red Hat: comparativa de tipos de tabla de particiones, Dell: FAQ SSD NVMe (MBR y GPT), Microsoft Learn: Windows and GPT FAQ. Windows incluye MBR2GPT para convertir un disco ya instalado de MBR a GPT sin perder datos (Microsoft Learn).

    4.3. Particiones especiales

    Partición Qué contiene
    ESP (sistema EFI) Cargadores de arranque UEFI en la carpeta EFI; imprescindible para arrancar
    Reservada (MSR) Espacio reservado de Microsoft, sin datos, para uso interno de Windows
    Recuperación Imagen de fábrica y entorno WinRE para restaurar sin medios externos
    Swap de Linux Área de intercambio: memoria virtual en disco

    Estas particiones no llevan letra en el Explorador: se gestionan con las herramientas de discos, y borrarlas rompe el arranque o la recuperación.

    4.4. Sistemas de archivos

    Sistema Límites y uso típico
    FAT32 Compatible con todo; máximo de 4 GiB por archivo. Pendrives de arranque e intercambio
    exFAT Sin el límite de 4 GiB ni registro de cambios; discos externos y tarjetas de gran capacidad
    NTFS Con journaling, permisos y cifrado; particiones de sistema en Windows
    ext4 Con journaling; particiones de sistema y de datos en Linux

    El journaling permite recuperar la coherencia tras un corte eléctrico: NTFS y ext4 lo tienen; FAT32 y exFAT no. El límite de 4 GiB de FAT32 es un dato clave al guardar imágenes de disco.

    4.5. Herramientas de particionado

    • Administración de discos (Windows): gráfico, incluido en el sistema: crear, formatear, cambiar letras y extender volúmenes.
    • diskpart (Windows): consola; mismas operaciones con órdenes (list disk, select disk, create partition, format).
    • GParted: gráfico y multiplataforma, arranca desde USB (GParted Live): crear, borrar, mover, redimensionar y copiar particiones preservando los datos (funcionalidades).
    • fdisk y parted (Linux): consola, particionado clásico.

    Normas de seguridad: copia de seguridad previa (toda operación puede fallar), esquema planificado antes de operar (tabla, número de particiones, tamaños y sistemas de archivos) y no interrumpir nunca una operación en curso (un redimensionado interrumpido puede dejar la partición inutilizable). Verificación cruzada del disco seleccionado antes de aplicar cambios: un error de disco no tiene marcha atrás.

    5. Instalación estándar vs preinstalación

    Criterio relacionado: CE 3.2 (diferencia entre instalación estándar y preinstalación o imagen).

    5.1. La instalación estándar

    Parte del medio original del sistema operativo y avanza por los diálogos del instalador (apartado 2.2), configurando cada equipo paso a paso: idioma, particiones, usuario, red, controladores y aplicaciones. Ofrece la personalización máxima y siempre instala la versión más actualizada del medio, a cambio de un tiempo de puesta a punto de horas por equipo.

    5.2. La imagen y la preinstalación

    Una imagen de software es una copia exacta y comprimida de un disco o partición de un sistema ya configurado (imagen maestra) que se vuelca sobre el equipo destino en minutos. La preinstalación OEM es el caso comercial: los equipos nuevos llegan con una imagen de fábrica y una partición de recuperación que permite restaurarlos sin medios externos. La instalación desatendida es el punto intermedio: instalación estándar automatizada con un archivo de respuestas.

    5.3. Comparativa

    Aspecto Instalación estándar Imagen / preinstalación
    Tiempo de puesta a punto Largo (horas con aplicaciones) Corto (minutos)
    Homogeneidad de los equipos Baja (configuración manual) Alta (equipos idénticos)
    Actualización del sistema Siempre la del medio Congelada: hay que regenerar la imagen
    Personalización Máxima La de la imagen base
    Mantenimiento en aulas y talleres Inasumible equipo a equipo Restauración rápida ante fallos

    Conceptos técnicos asociados: imagen de disco completo frente a imagen de particiones; clonación de bloques en uso (solo lo ocupado, con compresión) frente a clonación bloque a bloque; imagen a archivo (device-image) frente a clonación directa (device-device); y generalización de la imagen maestra (identificadores, licencias, SID) con utilidades como Sysprep antes de duplicarla en muchos equipos.

    6. Recuperación del sistema

    Criterio relacionado: CE 3.6 (restauración de imágenes desde distintas ubicaciones).

    6.1. Vías de recuperación

    • Restauración de una imagen propia: se vuelve a volcar la última imagen buena sobre el disco (apartado 8). Es la vía profesional en talleres y aulas.
    • Herramientas propias de Windows (WinRE): el entorno de recuperación se abre desde el arranque avanzado y ofrece reparación de inicio, restaurar desde una imagen de sistema, desinstalar actualizaciones y "Restablecer este equipo" (reinstala Windows conservando o borrando los archivos personales).
    • Partición de recuperación OEM: la imagen de fábrica del fabricante, invocada con la tecla de recuperación del equipo al arrancar (F11 o similar según marca).
    • Puntos de restauración: devuelven la configuración del sistema a un estado anterior (útiles tras un controlador o actualización problemáticos, no ante fallos de disco).

    6.2. Restauración desde distintas ubicaciones

    El criterio exige saber restaurar la misma imagen desde ubicaciones distintas:

    • Repositorio local: USB externo o segundo disco conectado al equipo (Clonezilla: local_dev).
    • Repositorio en red: servidor SSH, recurso compartido Samba o NFS; hay que aportar dirección, ruta y credenciales. Es la base del despliegue de aulas.
    • NAS o almacenamiento centralizado del centro: repositorio compartido para todo el taller.

    6.3. Precauciones y verificación posterior

    • La restauración sobrescribe por completo el disco destino: verificación cruzada del disco (número, nombre y tamaño) antes de confirmar; Clonezilla pide doble confirmación.
    • Tras restaurar: comprobar el arranque, revisar controladores si el hardware destino difiere del origen, y verificar activación de licencias.
    • Comprobar la tabla de particiones y los datos restaurados (los archivos de prueba deben estar exactamente donde estaban).

    7. Soportes de memoria auxiliar

    Criterio relacionado: CE 3.1 (soportes adecuados para almacenar y restaurar imágenes).

    La imagen se guarda en un soporte distinto del disco que se copia: de ahí el nombre de memoria auxiliar. En esta unidad juegan dos papeles distintos: medio de arranque de la utilidad (el USB con Clonezilla o GParted) y repositorio donde se guarda la imagen.

    7.1. Disco duro externo

    • Tipo: soporte magnético de gran capacidad (del orden de terabytes) y buen precio por GB.
    • Papel: repositorio habitual de las imágenes de un taller: admite varias imágenes completas, con conexiones rápidas (USB 3.x) y suficiente velocidad para crear y restaurar en tiempos razonables.
    • Criterios de uso: formateado en NTFS o exFAT (no en FAT32, por el límite de 4 GiB por archivo); conservar más de una copia de las imágenes críticas porque el propio soporte puede fallar.

    7.2. USB (memorias flash y SSD externos)

    • Tipo: soporte electrónico de estado sólido, sin partes móviles: resistentes a golpes, rápidos en lectura y de capacidad media.
    • Papel doble:
    • Medio de arranque de las utilidades (GParted Live, Clonezilla Live): bastan 2-8 GB.
    • Repositorio de imágenes puntual o de campo: cómodo para llevar la imagen de un cliente al equipo que se repara.
    • Limitaciones: capacidad más reducida y coste por GB superior al disco externo; los USB de baja calidad o muy usados pueden degradarse. La velocidad del puerto (USB 2.0 frente a 3.x) marca el tiempo de creación y restauración.

    7.3. Almacenamiento en la nube

    • Tipo: soporte en red bajo demanda: capacidad elástica, sin hardware propio que administrar.
    • Papel: copia de seguridad de imágenes fuera del centro (protección ante robo, incendio o fallo del repositorio local) y acceso desde cualquier punto con conexión.
    • Limitaciones: depende de la conexión (crear o restaurar una imagen de decenas de GB por red doméstica es lento), coste recurrente por suscripción, y consideraciones de privacidad y protección de datos: las imágenes contienen sistemas completos con datos personales.

    7.4. Otros soportes de referencia

    • Ópticos (CD/DVD/BD): capacidad limitada (0,7 a 25 GB), lentos y sensibles a rayaduras; cada vez más residuales, aunque los discos de rescate antiguos siguen apareciendo en talleres.
    • NAS y servidor del centro: almacenamiento en red compartido; el repositorio natural de las imágenes de un aula completa, accesible desde Clonezilla por Samba, SSH o NFS.

    7.5. Criterios de selección del soporte

    1. Capacidad: debe caber la imagen completa (la imagen comprimida suele ocupar bastante menos que el disco origen, pero conviene estimar antes).
    2. Sistema de archivos: FAT32 no admite archivos de más de 4 GiB; el repositorio debe formatearse en NTFS o exFAT.
    3. Velocidad: condiciona el tiempo de creación y restauración (un USB 2.0 puede multiplicar por diez la espera).
    4. Fiabilidad y durabilidad: el repositorio debe conservar la imagen durante meses.
    5. Coste por GB y portabilidad: según el escenario (taller, aula, campo).

    8. Creación de imágenes

    Criterios relacionados: CE 3.5 (utilidades y soportes para realizar imágenes), CE 3.6 (restauración).

    8.1. Panorama de herramientas

    • Clonezilla Live: utilidad libre de referencia; arranca desde USB, crea y restaura imágenes en repositorios locales o de red (SSH, Samba, NFS) y copia solo los bloques en uso con compresión.
    • Utilidades de Windows: copia de seguridad de imagen del sistema, unidad de recuperación y "Restablecer este equipo" (WinRE).
    • Soluciones comerciales: Macrium Reflect, Acronis True Image / Cyber Protect: interfaz cómoda, programación y soporte del fabricante.
    • Herramientas de bajo nivel: dd (copia bit a bit, incluido el espacio vacío) y partclone/partimage (solo bloques en uso): los motores internos que emplean las utilidades anteriores.

    8.2. Clonezilla: modos y operaciones

    • Modo device-image: guarda el disco en un archivo dentro de un repositorio. Operaciones: savedisk (imagen del disco completo), saveparts (imagen de particiones concretas), restoredisk (volver a volcar la imagen de un disco) y restoreparts (restaurar solo algunas particiones).
    • Modo device-device: clonación directa de un disco a otro, sin imagen intermedia; para duplicar o migrar discos.
    • El modo principiante oculta las opciones avanzadas y es suficiente para el trabajo habitual; la imagen resultante es una carpeta con varias partes (de 4 GB máximo cada una, por el límite de FAT32), un registro y sumas de comprobación.

    8.3. Flujo de creación (savedisk)

    1. Arrancar desde el USB de Clonezilla (secuencia de arranque de la UD 2).
    2. Elegir el repositorio de destino: disco local (local_dev), SSH, Samba o NFS.
    3. Elegir origen y nombre: savedisk o saveparts, con un nombre normalizado (equipo, fecha y versión, p. ej. AULA21-PC07_2026-11-13_v2).
    4. Ejecutar y verificar: compresión por defecto y comprobación final de la imagen.

    8.4. Flujo de restauración (restoredisk)

    1. Arrancar el USB de Clonezilla y elegir el repositorio donde reside la imagen (el mismo tipo donde se guardó).
    2. Seleccionar la imagen de la lista del repositorio.
    3. Seleccionar el disco destino con verificación cruzada: el disco destino se sobrescribe por completo.
    4. Confirmar dos veces y dejar que Clonezilla vuelque la imagen.
    5. Verificar después: arranque, tabla de particiones, datos, controladores y activación si cambió el hardware.

    8.5. Buenas prácticas del técnico

    • Nombrar y documentar cada imagen (equipo, fecha, contenido): una imagen sin nombre es una imagen perdida.
    • Verificar la integridad tras crearla: una imagen corrupta solo se descubre al restaurarla, cuando ya es tarde.
    • Conservar más de una copia en soportes distintos: el repositorio también puede fallar.
    • Caso de uso del aula: una imagen maestra generalizada (Sysprep) restaurada en todos los equipos deja el aula idéntica y lista para examinar; la restauración desde el NAS del centro evita llevar el repositorio equipo a equipo.
