    • CE 3.2. Descripción detallada de las distintas formas de virtualización (servidores, almacenamiento, red).

    • CE 3.4. Evaluación de ventajas y desventajas de diferentes enfoques de virtualización.

    ¿QUE ES LA VIRTUALIZACIÓN?

    En su definición más fundamental, podemos decir que la virtualización es una técnica de abstracción de hardware. Esta consiste en la creación de una capa de software, denominada hipervisor o Virtual Machine Monitor (VMM), que abstrae (separa o segmenta) los recursos físicos del sistema (CPU, memoria, almacenamiento, interfaces de red...) para presentarlos como múltiples entornos de ejecución independientes, llamados máquinas virtuales (VM).

    A diferencia de la emulación, que traduce instrucciones entre distintas arquitecturas mediante software, la virtualización ejecuta la mayoría de las instrucciones directamente en la CPU física subyacente para garantizar un alto rendimiento.

    ¿QUE APORTA?

    La virtualización ha transformado la infraestructura tecnológica, optimizando el uso del hardware mediante la consolidación (unificar varias máquinas físicas en una sola, en forma de VMs) de servidores, permitiendo ejecutar de forma aislada y segura (SANDBOXING) múltiples sistemas operativos y aplicaciones legadas (LEGACY = sofware aún crítico para una empresa, pero que ya no recibe soporte) en un mismo entorno.

    Además, esta independencia del software respecto al hardware, no solo garantiza la compatibilidad con sistemas heterogéneos, sino que también aporta una flexibilidad y portabilidad excepcionales que facilitan el despliegue rápido, la migración en caliente y una alta disponibilidad ante cualquier fallo.

    CATEGORÍAS DE VIRTUALIZACIÓN

    Podemos diferenciar distintas categorías de virtualización, según el recurso físico sobre el cual se aplica la capa de abstracción:

    Virtualización de Servidores (o Cómputo)

    Es la forma clásica de virtualización. Consiste en abstraer el hardware de un servidor físico (CPU, arquitectura de memoria, buses) para segmentarlo en múltiples máquinas virtuales (VMs), cada una ejecutando su propio sistema operativo (Guest OS).

    • Mecanismos clave:
    • Trap-and-Emulate / Binary Translation: Métodos históricos para interceptar instrucciones privilegiadas del Guest OS.

    • Virtualización asistida por hardware (Intel VT-x, AMD-V): Introduce modos de ejecución específicos en el procesador (p. ej., VMX Root y Non-Root Operation) para que las instrucciones no privilegiadas se ejecuten nativamente y las sensible interpelen directamente al hipervisor (VM-Exits).

    • Paradigmas principales:

    • Virtualización completa (Full Virtualization): El SO huésped no requiere modificación; cree interactuar con hardware real.
    • Paravirtualización (Paravirtualization): El SO huésped se modifica explícitamente para llamar al hipervisor mediante hypercalls, eliminando la necesidad de emular dispositivos rígidos y aumentando la eficiencia de E/S.

    Virtualización de Almacenamiento

    Abstrae los dispositivos físicos de almacenamiento (discos duros, SSDs, arrays SAN/NAS) creando un único grupo lógico de almacenamiento (storage pool) que se distribuye de manera flexible entre los sistemas.

    • Niveles de abstracción:
    • A nivel de bloque (p. ej., SAN / SDS - Software-Defined Storage): Oculta la complejidad de las cabinas físicas. El sistema lógico asigna LUNs (Logical Unit Numbers) virtuales y volúmenes dinámicos sin importar la ubicación física de los sectores.

    • A nivel de archivo (p. ej., NAS virtual): Abstrae los sistemas de archivos mediante espacios de nombres globales (Global Name Spaces).

    • Técnicas destacadas:

    • Aprovisionamiento fino (Thin Provisioning): Asignación bajo demanda de espacio en disco en lugar de la reserva estática inicial.
    • Capas dinámicas (Tiering): Movimiento automático de bloques de datos entre medios rápidos (NVMe/SSD) y lentos (HDD) según la frecuencia de acceso.

    Virtualización de Red (SDN)

    Desacopla los servicios de red de la infraestructura de hardware subyacente. En la literatura académica, esto se formaliza mediante el paradigma de Redes Definidas por Software (SDN) y Virtualización de Funciones de Red (NFV).

    • Desacoplamiento de planos:
    • Plano de Control (Control Plane): Centralizado lógicamente en un software controlador que decide cómo se encamina el tráfico.

    • Plano de Datos (Data/Forwarding Plane): Conmutadores físicos o virtuales (vSwitches) que solo ejecutan el reenvío de paquetes dictado por el plano de control.

    • Redes superpuestas (Overlay Networks): Encapsulación de tramas de red L2 sobre protocolos de transporte L3 (como VXLAN, NVGRE o GENEVE), permitiendo crear millones de redes virtuales aisladas sobre una única infraestructura física (underlay).

    • NFV: Reemplazo de appliances propietarios (firewalls, balanceadores de carga, routers) por software que corre en VMs o contenedores.

    Virtualización a Nivel de Sistema Operativo (Contenedores)

    A diferencia de la virtualización de servidores, no se virtualiza el hardware subyacente mediante un hipervisor, sino que se comparte el mismo núcleo (kernel) del sistema operativo anfitrión.

    • Mecanismos del kernel (principalmente en Linux):
    • Namespaces: Proveen aislamiento de vista (procesos, red, montaje de archivos, usuarios, IPC).

    • Control Groups (cgroups): Proveen limitación y contabilidad de recursos (CPU, memoria, E/S de disco).

    • Ventajas frente a las VMs: Menor sobrecarga (overhead), arranque en milisegundos y mayor densidad de instancias por host, a costa de compartir el mismo kernel y ofrecer un aislamiento ligeramente menos estricto que el hardware dedicado.

    Virtualización de Escritorio (VDI)

    Separa el entorno de escritorio del usuario (sistema operativo, aplicaciones y datos) del dispositivo físico del cliente (thin client, PC o móvil).

    • Enfoque centralizado (VDI - Virtual Desktop Infrastructure): Los escritorios se ejecutan como VMs alojadas en un centro de datos. La interacción se realiza mediante protocolos de visualización remota (p. ej., PCoIP, ICA/HDX) encargados de comprimir y transmitir los eventos de teclado/ratón y los píxeles de pantalla.
    • Enfoque de aplicación (Application Virtualization): Encapsulamiento de una aplicación individual para que se ejecute en un entorno aislado sin interferir con las librerías del sistema operativo local (p. ej., Microsoft App-V).

    Virtualización de Memoria

    Abstrae la memoria física del sistema ($RAM$) separándola del espacio de direcciones que ven los procesos o las máquinas virtuales.

    • Traducción de Direcciones de Dos Niveles (en VMs):
    • La VM traduce una Dirección Virtual del Huésped (GVA) a una Dirección Física del Huésped (GPA).

    • El hipervisor traduce la GPA a la Dirección Física del Host (HPA).

    • Optimización por Hardware: Se realiza mediante EPT (Extended Page Tables en Intel) o NPT/RVI (Nested Page Tables en AMD), reduciendo drásticamente la sobrecarga que imponían históricamente las tablas de páginas en sombra (Shadow Page Tables) implementadas puramente por software.

    MÉTODOS DE IMPLEMENTACIÓN

    La clasificación de las implementaciones de virtualización se basa en la ubicación de la capa de abstracción (virtualization layer) y en el grado de modificación del sistema operativo huésped (Guest OS).

    Virtualización Tipo 1 o "Bare-Metal" (Nativa)

    El hipervisor o Virtual Machine Monitor (VMM) se ejecuta directamente sobre el hardware físico, sin ningún sistema operativo intermediario. El hipervisor actúa como el propio núcleo del sistema.

    • Mecanismo de funcionamiento: El hipervisor administra de forma directa la CPU, la memoria principal y las interrupciones. Controla la asignación de hardware y programa la ejecución de las máquinas virtuales.
    • Ventajas:
    • Alto rendimiento y baja latencia: Al no existir capas adicionales de SO anfitrión, la sobrecarga (overhead) de gestión es mínima.

    • Mayor aislamiento y seguridad: Se reduce la superficie de ataque al no depender de las vulnerabilidades de un SO multipropósito subyacente.

    • Inconvenientes:

    • Gestión de controladores de dispositivos (drivers) más compleja, ya que el hipervisor debe incluir soporte específico para el hardware.

    • Ejemplos académicos/comerciales: VMware ESXi, Xen, KVM (convertido en Tipo 1 mediante el módulo del kernel de Linux), Microsoft Hyper-V.

    Virtualización Tipo 2 o "Hosted" (Alojada)

    El hipervisor se ejecuta como un proceso o aplicación dentro de un sistema operativo anfitrión (Host OS) convencional.

    • Mecanismo de funcionamiento: Las peticiones de hardware formuladas por las VMs pasan por el hipervisor, este las traduce a llamadas al sistema (system calls) del SO anfitrión, y es el SO anfitrión quien finalmente interactúa con el hardware.
    • Ventajas:
    • Amplia compatibilidad de hardware: Utiliza la base de controladores (drivers) ya instalada en el SO anfitrión.

    • Facilidad de instalación y gestión: Funciona como cualquier software de escritorio estándar.

    • Inconvenientes:

    • Sobrecarga de rendimiento elevada: Cada operación de E/S o llamada al sistema debe atravesar múltiples capas contextuales (cambios de contexto entre espacio de usuario y espacio de núcleo tanto en el huésped como en el anfitrión).

    • Ejemplos académicos/comerciales: Oracle VirtualBox, VMware Workstation, QEMU (en modo emulación pura).

    Virtualización Completa (Full Virtualization)

    Método de implementación donde el hardware físico se abstrae por completo de manera que el sistema operativo huésped no requiere ningún tipo de modificación; "cree" estar ejecutándose sobre un equipo físico real.

    • Evolución técnica de la implementación:
    • Traducción Binaria Dinámica (Dynamic Binary Translation): Históricamente desarrollada por VMware para superar las limitaciones de la arquitectura x86 (teorema de Popek-Goldberg). El hipervisor escanea el código ejecutable del huésped en tiempo real, intercepta las instrucciones sensibles o privilegiadas que se ejecutan en anillo 1/2/3 y las reemplaza por secuencias de instrucciones seguras.
    • Virtualización Asistida por Hardware (Hardware-Assisted Virtualization): Estándar actual desde la introducción de las extensiones Intel VT-x y AMD-V. El procesador físico implementa modos de operación específicos:
    • VMX Root Operation: Modo con privilegios completos donde se ejecuta el hipervisor.
    • VMX Non-Root Operation: Modo restringido donde se ejecuta el Guest OS. Las instrucciones sensibles provocan un cambio de contexto automático hacia el hipervisor mediante un evento denominado VM-Exit.

    Paravirtualización (Paravirtualization)

    Método formalizado por Barham et al. (2003) en el diseño inicial de Xen. Consiste en modificar intencionadamente el código fuente del sistema operativo huésped para que sea consciente de que se está ejecutando dentro de un entorno virtualizado.

    • Mecanismo de funcionamiento:
    • Se eliminan las instrucciones sensibles no virtualizables del kernel del huésped y se reemplazan por llamadas explícitas al hipervisor, denominadas hiperllamadas (hypercalls), análogas a las llamadas al sistema (syscalls).

    • Los controladores de dispositivos no emulan componentes de hardware rígidos (como tarjetas de red antiguas), sino que utilizan arquitecturas de controladores divididas (split drivers): un controlador frontal (frontend) en el huésped se comunica mediante memoria compartida con un controlador trasero (backend) en el hipervisor.

    • Ventajas: Elimina la necesidad de traducción binaria o trampeo continuo por hardware, reduciendo significativamente la latencia en operaciones de entrada/salida (E/S).

    • Inconvenientes: Requiere acceso al código fuente del sistema operativo para modificarlo (incompatible con sistemas operativos propietarios cerrados como Windows no adaptados).

    Virtualización a Nivel de OS / Basada en Contenedores

    Implementación donde no se utiliza un hipervisor ni se crean máquinas virtuales completas. En su lugar, el propio núcleo del sistema operativo anfitrión gestiona múltiples instancias de espacio de usuario aisladas entre sí.

    • Mecanismos clave en el núcleo (Linux):
    • Namespaces: Asignan a cada contenedor su propia vista privada de los recursos del sistema (PID, red, puntos de montaje, usuarios, IPC).

    • Control Groups (cgroups): Garantizan la contabilidad, priorización y restricción de recursos físicos (cuotas de CPU, límite de memoria RAM, ancho de banda de disco).

    • Diferencia fundamental: Todos los contenedores comparten el mismo kernel del sistema operativo anfitrión, eliminando el coste de memoria y cómputo que supone ejecutar un kernel independiente por cada instancia.

    • Ejemplos: LXC/LXD, Docker, Podman, FreeBSD Jails, Solaris Zones.

    TECNOLOGÍAS ESPECÍFICAS DE VIRTUALIZACIÓN

    La virtualización comercial e industrial está dominada por un grupo selecto de tecnologías desarrolladas por las compañías líderes del sector. A continuación, se detallan las principales propuestas tecnológicas de cada una:

    VMware (Broadcom)

    Historicamente pionera en la traducción binaria y el desarrollo de hipervisores empresariales, VMware fundamenta su ecosistema en la arquitectura de hipervisor bare-metal.

    • VMware ESXi: Es su hipervisor Tipo 1 (bare-metal). Posee un micronúcleo propio (VMkernel) que gestiona directamente la memoria, los procesos y el acceso de E/S al hardware sin depender de un sistema operativo subyacente.
    • VMware vSphere: La plataforma de virtualización a nivel de centro de datos que combina ESXi con vCenter Server (el plano de gestión centralizado).
    • Tecnologías clave:
    • vMotion: Algoritmo académico de referencia para la live migration (migración en vivo de VMs en ejecución entre hosts físicos utilizando la red sin interrupción de servicio).
    • DRS (Distributed Resource Scheduler): Balanceo dinámico de carga basado en el análisis de consumo de CPU y RAM.
    • vSAN (Storage Area Network virtual): Tecnología de almacenamiento definido por software (SDS) que agrupa los discos locales de los hosts ESXi en un pool de almacenamiento distribuido.

    Microsoft

    Microsoft evolucionó desde la virtualización alojada hacia un modelo de particionamiento basado en hipervisor nativo.

    • Microsoft Hyper-V: Hipervisor Tipo 1 basado en microkernel con arquitectura de particiones.
    • Partición Primaria/Padre (Parent Partition): Ejecuta Windows Server y gestiona la pila de virtualización y el acceso directo a controladores.

    • Particiones Hijas (Child Partitions): Entornos aislados donde se ejecutan los Guest OS. La comunicación de alta velocidad entre particiones se realiza a través del canal de bus sintético VMBus.

    • Azure Stack HCI: Solución de infraestructura hiperconvergente (HCI) orientada a entornos híbridos, que combina Hyper-V con tecnologías de red (Software-Defined Networking) y almacenamiento (Storage Spaces Direct) conectadas con la nube de Azure.

    Red Hat (IBM)

    Red Hat centra su estrategia de virtualización en el código abierto empresarial y la convergencia entre máquinas virtuales y contenedores.

    • KVM (Kernel-based Virtual Machine): Módulo del núcleo Linux que transforma el kernel en un hipervisor Tipo 1. Maneja cada VM como un proceso estándar de Linux programado por el scheduler del sistema.
    • QEMU: Utilizado conjuntamente con KVM para realizar la emulación de componentes de hardware y la gestión del espacio de usuario.
    • Red Hat OpenShift Virtualization: Basado en el proyecto de código abierto KubeVirt. Permite ejecutar y gestionar máquinas virtuales tradicionales dentro de la misma plataforma de orquestación de contenedores (Kubernetes), permitiendo una gestión unificada de cargas legacy y nativas de la nube.

    Citrix Systems (Cloud Software Group)

    Citrix ha centrado históricamente sus tecnologías en la virtualización de escritorios, aplicaciones y la capa de hipervisor optimizada para E/S.

    • XenServer (Citrix Hypervisor): Hipervisor Tipo 1 desarrollado comercialmente sobre el motor de paravirtualización y código abierto Xen.
    • Dominio 0 (Dom0): Máquina virtual privilegiada inicial que controla el plano de gestión e interactúa con el hipervisor Xen subyacente.

    • DomU: Máquinas virtuales de usuario no privilegiadas.

    • Citrix DaaS / Virtual Apps and Desktops: Tecnología referente en la virtualización de aplicaciones y escritorios (VDI). Utiliza el protocolo propietario HDX / ICA (Independent Computing Architecture) para la compresión y transmisión eficiente del flujo de pantalla y eventos de entrada a través de redes WAN o de bajo ancho de banda.

    Proxmox Server Solutions (Alternativa Open Source de Nivel Empresarial)

    Muy relevante en el sector por su implementación de código abierto sin licencias por socket.

    • Proxmox VE (Virtual Environment): Plataforma de gestión de virtualización empresarial basada en Debian GNU/Linux.
    • Doble motor de virtualización:
    • KVM: Para virtualización completa de sistemas operativos heterogéneos.
    • LXC (Linux Containers): Para la virtualización a nivel de sistema operativo de alta densidad.

    ¿Y VIRTUAL BOX?

    Quizás alguien haya echado en falta una de las tecnologías más conocidas de virtualización, que solemos usar en el aula. Esto se debe a que la clasificación anterior, se centra en el ámbito empresarial, orientado a sistemas distribuidos y centros de datos (gestión masiva de infraestructura).

    Mientras que VirtualBox está enfocado sobre todo para uso individual o de escritorio, dedicado a la realización de pruebas de software, entornos de laboratorio o ejecución de aplicaciones aisladas. Pero un pequeño resumen de la herramienta sería el siguiente:

    • Tecnología: Oracle VM VirtualBox.
    • Tipo de Hipervisor: Tipo 2 (Hosted).
    • Posicionamiento: Es la herramienta de virtualización multiplataforma de código abierto (bajo licencia GPLv3, con extensiones bajo licencia PUE) más popular del mundo para uso en estaciones de trabajo.
    • Fortalezas:
      • Multiplataforma universal: Se ejecuta sobre hosts Windows, Linux, macOS y Solaris.
      • Facilidad de despliegue: Ideal para laboratorios de prueba, docencia académica y desarrollo de software local sin necesidad de infraestructura dedicada.
      • Integración con Vagrant: Ampliamente utilizado en metodologías DevOps para aprovisionar entornos de desarrollo reproducibles mediante código.

    BENEFICIOS Y LIMITACIONES DE LA VIRTUALIZACIÓN

    A nivel general, se resumen a continuación los beneficios estratégicos y las limitaciones fundamentales de la virtualización:

    BENEFICIOS

    • Optimización y consolidación del hardware: Permite elevar la tasa media de uso de la CPU y memoria en los servidores físicos (pasando de promedios del 10-15% en sistemas dedicados a cotas del 70-80%), reduciendo el número de equipos necesarios.
    • Reducción de costes (CapEx y OpEx): Al disminuir la infraestructura física, decrece la inversión en adquisición de servidores (CapEx), así como los gastos asociados al consumo eléctrico, espacio físico en el centro de datos y sistemas de refrigeración (OpEx).
    • Aislamiento y tolerancia a fallos (Sandboxing): La separación lógica estricta entre instancias impide que un error crítico (kernel panic), un fallo de software o un incidente de seguridad en una máquina virtual o contenedor afecte al resto de entornos o al host físico.
    • Continuidad de negocio y rápida recuperación: La encapsulación de todo el estado de un entorno en archivos facilita la realización de instantáneas (snapshots), copias de seguridad consistentes y la migración en vivo (live migration) entre servidores físicos para mantenimiento sin parada de servicio.
    • Flexibilidad y agilidad operativa: El tiempo de aprovisionamiento de nuevos servidores o entornos de pruebas pasa de semanas (al requerir compra e instalación física) a minutos u ordenes de segundos mediante código o plantillas.

    LIMITACIONES

    • Sobrecarga de rendimiento (Overhead): Aunque es mínima en soluciones modernas (<2-5% en Tipo 1 asistido por hardware), la capa de abstracción añade cierta latencia en la traducción de instrucciones y en la gestión de la memoria y la entrada/salida (E/S).
    • Punto único de fallo (Single Point of Failure): La concentración de múltiples máquinas virtuales o contenedores en un solo servidor físico implica que una avería en el hardware subyacente puede interrumpir la totalidad de los servicios albergados si no existe un clúster de alta disponibilidad (HA).
    • Degradación por contención de recursos (Resource Contention): El fenómeno del "vecino ruidoso" (noisy neighbor) ocurre cuando una máquina virtual realiza un consumo intensivo e imprevisto de CPU, ancho de banda o E/S de disco, afectando al rendimiento del resto de instancias en el mismo host.
    • Complejidad de gestión y licenciamiento: Requiere herramientas especializadas de orquestación, conocimientos técnicos avanzados en redes/almacenamiento virtual y esquemas de licencias de software que en ocasiones penalizan la ejecución sobre recursos virtualizados (per-socket o per-vCPU).
    • Incompatibilidad con hardware específico o en tiempo real: Las aplicaciones que requieren acceso directo y de ultrabaja latencia a componentes físicos específicos (como ciertas tarjetas de procesamiento de señal o sistemas empotrados de tiempo real estricto) pueden resentirse ante la capa de abstracción.

    VIRTUALIZACIÓN CON PROXMOX

    CREAR PLANTILLA MV UBUNTU

    Abrimos la consola del nodo Proxmox sobre el que vayamos a trabjar y creamos una máqina virtual con el siguiente comando:

    qm create 900 --name plantilla-ubuntu-2204 \
--ostype=l26 \
--scsihw virtio-scsi-single --agent enabled=1 \
--cpu x86-64-v2-AES \
--memory 2048 \
--net0 virtio,bridge=vmbr0,firewall=1 \
-ide2 none,media=cdrom

    Añadimos una unidad cloud-init que servirá para configurar varios parametros de la máquina la primera vez que se arranque:

    qm set 900 --ide0 local-lvm:cloudinit

    Luego establecemos los valores para los parámetros del cloud-init:

    qm set 900 --ciuser profe \
--cipassword profe \
--sshkey ~/.ssh/id_rsa.pub \
--ipconfig0 ip=dhcp

    Regeneramos la imagen de la máquina incluyendo el cloud-init:

    1. En el panel izquierdo, seleccionar nuestra máquina virtual: 900.

    2. Dentro de ella, selecciónar la opción Cloud-Init.

    3. Pulsar el botón Regenerate image.

    Volvemos a la consola de nuestro nodo y añadimos un interfaz serial para nuestra máquina virtual:

    qm set 900 --serial0 socket --vga serial0

    Descargamos la imagen cloud de Ubuntu:

    wget https://cloud-images.ubuntu.com/minimal/releases/jammy/release/ubuntu-22.04-minimal-cloudimg-amd64.img

    Cambiamos el tamaño de la imagen descargada:

    qemu-img resize ubuntu-22.04-minimal-cloudimg-amd64.img 16G

    Importamos la imagen ubuntu al disco local definido en nuestro Datacenter PROXMOX:

    qm importdisk 900 ubuntu-22.04-minimal-cloudimg-amd64.img local-lvm

    Ahora configuramos el disco scsi0 de nuestra máquina virtual, con el disco que nos ha generado el comando anterior:

    qm set 900 --scsi0 local-lvm:vm-900-disk-0,discard=on,iothread=1,ssd=1

    Cambiamos el orden de arranque de la máquina:

    1. Seleccionar la máquina virtual: 900

    2. Seleccionar la opción Opciones

    3. Seleciconar el elemento Orden de arranque y pulsar el botón Editar:

      • Activar el disco scsi0

      • Arrastrarlo a la segunda posición (dejando el CDROM como primera opción por si algún día se necesita iniciar mediante una ISO)

    Volvemos a la consola de nuestro nodo Proxmox y convertimos la máquina en plantilla:

    qm template 900

    CLONACIÓN DE LA PLANTILLA

    Para clonar nuestra plantilla, desde el shell del nodo Proxmox, ejecutamos:

    qm clone 900 101 --name ubuntu-clon1 --full 1 --storage NASinformatica

    Modificando el valor 101 por el ID que queramos darle a la máquina clonada, tambien el nombre que se le quiera dar a la máquina; y por último indicando en donde queremos que se almacene su imagen (en este ejemplo usamos un NAS que tenemos conectado a Proxmox).

    PRIMER INICIO DE LA MÁQUINA

    Antes de arrancar la máquina clonada, personalizamos los valores de username, password y direccionamiento IP:

    qm set 101 --ciuser clon1 --cipassword clon1
qm set 101 --ipconfig0 ip=172.21.184.41/16,gw=172.21.0.254

    Si queremos asignar los clones a grupos de usuarios para que solo sean visibles por ellos, podemos hacerlo con el comando:

    pveum acl mod /vms/101 --group Grupo1_ASIR --role "PVEVMAdmin"

    Es un ubuntu minimal, por lo que trae lo justo. Deberemos ir instalandole las herramientas que necesitemos:

    apt install nano
apt install openvswitch-switch

    Además, para utilizar el DNS local añadiendo entradas en el fichero /etc/hosts y que no perdamos los datos, debemos editar el siguiente fichero y comentamos la línea que dice - update_etc_hosts:

    sudo nano /etc/cloud/cloud.cfg
